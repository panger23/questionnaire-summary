# 鲁审 · 汇卷（扫描件智能汇总）

把扫描的《审计项目组组员满意度调查问卷》PDF 自动整理成汇总 Excel。

> **鲁审** 是产品名（山东 + 审计），**汇卷** 是当前模块名（扫描件 → 汇总表）。
> 这样以后新增功能可以按模块扩展（鲁审 · 台账、鲁审 · 核验…），名字不会和功能对不上。
> 仓库名仍是 `questionnaire-summary`。

## 它做什么

- 识别每页问卷属于哪个分行、组长助手（代职人）、审计组长
- 识别 5 项评价指标各自勾在 10~1 分的哪一列
- 分数 = 5 项分值之和（**不读手写总分**，手写内容一律忽略）
- 自动跳过扫描仪夹进来的空白页，并把跳过的页码列出来
- 生成 Excel：`汇总`（分行分列、每人分数、平均分，全部公式）+ `明细`（页码、**审计组长、组长助手**、双通道结果、标黄标记）+ `说明`

## 三档识别方式

| 方式 | 需要网络 | 花费 | 说明 |
|---|---|---|---|
| **纯本地识别**（默认） | 不需要 | 0 元 | 完全离线，图像墨迹分析判列 |
| **本地 + 复核可疑页**（推荐） | 需要 | 约 ¥0.01 | 只有被标黄的页（一般 3–6 页）才送 LLM 复核，其余不花钱 |
| **本地 + 全量复核** | 需要 | 约 ¥0.2 | 54 页全部送 LLM 交叉校验，最稳 |

实测同一份 54 页问卷：全量复核要 270 次模型调用，只复核可疑页只要 **15 次**（3 页 × 5 行）。

LLM 配置只在运行时由用户填写，**不写入代码、不入库**。

LLM 通道整体不可用时（额度用完、Key 失效、断网），程序**不会报错退出**，而是自动退回纯代码模式，
并在网页顶部/命令行给出明确提示——纯代码模式本身是完整可用的。

## 用网页操作（推荐，给不懂代码的人用）

**双击 `启动网页.command`** → 浏览器自动打开 → 拖入 PDF → 等进度 → 看结果 / 改分 / 下载 Excel。

- 服务只监听 `127.0.0.1`，**同一内网里的其他人也访问不到**，Key 和数据都只在你本机
- 第一次运行会自动装依赖（约 2 分钟），之后秒开
- 关掉终端窗口就停止服务；PDF 只存在内存里，处理时用临时文件，处理完立刻删除

网页里能做：

| 功能 | 说明 |
|---|---|
| 上传 | 拖入 PDF；**LLM 复核默认关闭**，需要时手动勾选 |
| 进度 | 分两个阶段显示：识别 x/54 页 → LLM 复核 x/270 行 |
| 汇总 | 分行分列、组员数量、代职人、每人分数、平均分，改分后实时重算 |
| 明细 | 每份一行，标黄行为待确认；分数可直接改 |
| 看原图 | 点「看原图」弹出该页扫描图，对着改分 |
| 采用LLM | 双通道不一致的行可一键采用 LLM 的 5 个分数 |
| 下载 | 生成带公式的 xlsx |
| 设置 | 填 API 地址 / 模型 / Key，可测试连接、清除 Key（Key 只存本机） |

## 命令行用法

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 纯代码模式（离线，约 35 秒）
.venv/bin/python -m src.cli "data/原始扫描件/调查问卷扫描件.pdf"

# 启用 LLM 复核（约 2 分钟，约 ¥0.2）
.venv/bin/python -m src.cli "data/原始扫描件/调查问卷扫描件.pdf" --llm
# 结果在 output/<文件名>_汇总_<时间>.xlsx
```

## 识别原理

> 目标是**通用**：不假设表格一定有多少行多少列、一定 10 档分。
> 结构、分值档位、行数都从图像和表头里推出来，换一份版式不同的 PDF 也能跑。

1. **渲染**：PDF 每页 → 300dpi 灰度图
2. **纠偏**：先直接找表格线；找不到就估计倾斜角（-2°~+2° 逐度试），转正后重试
3. **找网格**：按行/列墨迹像素数检出表格线；再由"等宽连续的一段竖线"推断出**分值列**，
   由"每个格子都印着字的那一行"推断出**表头行**，进而确定**有哪几行要打分**
4. **分值档位**：只 OCR 一次表头（整份文档复用），读出每列印的是"10分/9分/…"，
   所以换成 5 档分、或者中间夹了「小计」列，都能自动对应，不靠写死
3. **判列（不靠 OCR）**：每个分值格算墨迹占比，取最高格。勾不是字符，OCR 认不出来（实测 270 格里 OCR 只吐出 22 个框），墨迹法则 270/270 全对
5. **读表头**：把表头那一行按竖线切成单元格、逐格 OCR（避免相邻两格被 OCR 粘成一段），
   拿项目名称 / 审计组长 / 组长助手；一份文档里项目名偶尔漏字，会做容错合并
6. **跳过空白页**：整页墨迹占比 < 1% 视为扫描仪夹进来的白纸（实测正常问卷约 4.4%，空白页 0.03%~0.04%），
   自动跳过、不计入问卷份数和平均分；页码会列在结果页和 Excel 的「说明」页里
7. **标黄**：墨迹跨格（次高格 ≥ 最高格 25%）、某行没找到勾、网格线数量异常、表头没识别出来、双通道不一致 —— 一律标黄交人工

## 标记的判定规则

填写人有两种标记方式：**打勾（√）** 和 **直接手写数字**。规则按顺序执行：

1. 一行里只要有标记，就以标记所在的格子为准（写数字时，该格对应的分值就是答案）
2. 同一行有多个格子都有笔迹时：**打勾（√）的那个是最终答案，画叉（×）视为作废**
3. 勾的尾巴扫过右侧竖线不算第二个标记，以笔迹主体所在格子为准

程序怎么落实这条规则：

- **代码通道（墨迹）**能定位"哪一格有墨"，但分不清 √ 和 ×，也分不清"两个标记"和"一个标记拖尾巴"
- **LLM 通道**逐行判 √ / × / 数字，并报出这一行有几个标记
- 两者不一致时，只有满足「两格墨量比 ≥ 50% **且** LLM 报 ≥ 2 个标记 **且** LLM 选的是次重那格」才自动采用 LLM 的结论，
  其余情况保持代码结论并在「明细」里写明"更像笔迹尾巴，未自动采用"

## 目录结构

```
.
├── data/            # 本地问卷数据（已被 .gitignore 排除，绝不入库）
│   ├── 原始扫描件/
│   └── 参考/
├── output/          # 生成的结果（不入库）
├── src/
│   ├── engine/      # 渲染、网格、墨迹判列、表头 OCR、流水线
│   ├── llm/         # LLM 复核通道（逐行裁图标注 + 调用 + 解析 + 配置）
│   ├── export/      # Excel 生成
│   └── cli.py
├── tests/
└── requirements.txt
```

## 数据安全

仓库是公开的，**任何问卷扫描件、图片、汇总表、API Key 都不允许进入版本库**。
`.gitignore` 第一段就把 `data/`、`*.pdf`、`*.xlsx`、配置文件全部挡掉；
CI 里另有硬检查：仓库中一旦出现 PDF/图片/表格文件，构建直接失败。

## 打包成免安装程序

源码需要 Python 环境；给不装 Python 的同事用，可以打包成免安装目录。

```bash
pip install pyinstaller
pyinstaller --clean --noconfirm packaging/app.spec
# 产物：dist/LuShen/  （双击 LuShen.exe 即启动网页）
```

- 打包配置在 `packaging/app.spec`（onedir 模式：启动快、杀软误报少）
- 用户说明在 `packaging/使用说明.txt`
- Windows 版由 GitHub Actions 在云端构建：见 `.github/workflows/build-windows.yml`
  （推送 `v*` 标签或手动触发，产物在 Actions 页面的 Artifacts 里下载）
